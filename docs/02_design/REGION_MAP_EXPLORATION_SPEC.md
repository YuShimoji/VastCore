```text
  Editor/ Vastcore.RegionMap.Editor.asmdef、メニューとバッチ入口、画面確認用スモーク

```

`Core/` は Unity の asmdef と `tools/RegionMapPreview` の両方から同じソースをコンパイルする。絵の調整は Unity を起動せずに数秒で回せる。既存の `Vastcore.Terrain` などへは依存しない（Deform・ProBuilder を巻き込まないため）。

### 生成の流れ（`RegionGenerator.Generate`）

1. `BuildBase`: ドメインワープした fBm で海陸を決め、外周は必ず海にする。山脈帯（ridged）と平野のマスクから隆起の強さを作る。
2. `Evolve`: Priority-Flood で窪地を埋めつつ下流→上流の順序を得て、流量を累積し、陰解法の stream power 侵食・斜面の上限（安息角）・斜面拡散を反復する。半解像度で反復の3/4、残りを全解像度で行う。「低い順に取り出す」待ち行列は高さ5mmごとの箱の列で持つ（`FlowRouter`。二分ヒープより速く、取り出す順は同じ）。
   - 流れ先は8方向から1つ選ぶが、比べ方をセルごとに決まった量だけずらし（`RegionSpec.FlowJitter`）、侵食の前と解像度を上げた直後に細かな凹凸を足す（`RoughnessMeters`）。これが無いと、なめらかな斜面で流れが平行な直線の束になり、そのまま溝として刻まれる。ゆらぎは seed から決まる固定値で、反復のたびには変わらない。
3. `BuildClimate`: 緯度と標高（6.5℃/km）から気温、西風が海で湿り陸と山で雨を落とす掃引から湿り気（雨陰が出る）。
4. `BuildRivers` / `ClassifyBiomes`: 流量のしきい値で川、気温×湿り気×標高×斜面でバイオーム。
5. `RegionAreaBuilder.Build`: 地域をエリアに分ける（下の「エリア」）。
6. `RegionSiteGenerator.Populate`: 候補点を地形で採点し、種類ごとに間隔を空けて選ぶ（下の「地点の置き方」）。

同じ `RegionSpec` からは同じ地域・同じエリア・同じ地点が出る（テストで固定）。

### エリア（`RegionAreaBuilder`、2026-11-22）

境界を地形の理由で決める。升目や距離では切らない。

1. 山地：標高を半径 n/160 でならし、線（最高標高の28%、下限450m）を超えるひと続きの高地を1エリアにする。陸の2%より狭いものは山地にしない。
2. 流域：残りの陸は、同じ河口へ注ぐ範囲（流域）ごとに分ける。境は分水嶺になる。流れの向きは侵食と同じ `FlowRouter` の結果を使う。
3. 小さな流域（陸の4.5%未満）は、境をいちばん長く接する隣の流域へ、流域ごと併せる。セル単位で最寄りへ寄せると境が直線になるので、そうしない。
4. 島：本土から離れた陸地は、陸の3%以下なら1つの島にする。ごく小さな島（0.06%未満）は最寄りのエリアへ入れる。
5. 岸に近い海（地図の幅の3.5%以内）は最寄りのエリアの「沖」、その外は外洋（エリア無し）。
6. 種類は地形から決める：山地／高地（平均標高が最高の20%以上）／丘陵（7%以上）／平野。雪原（寒冷地が4割以上）と砂漠（乾燥地が35%以上）は上書き。山地に6割以上囲まれた流域は盆地。
7. 呼び名は「方角＋種類」（例「中央の山地」）。方角は地図を3×3に分けた位置。同じ名前が重なる時は広い順に「第二」「第三」を付ける。名前を置く位置は、境界からいちばん離れた所。

`RegionArea` は、番号・種類・呼び名・区分けの根拠の文・名前の位置・面積・平均と最高の標高・主な土地・地点の数を持つ。

### 地点の置き方（`RegionSiteGenerator`）

置き方は確率の計算ではなく、規則による適合度の採点。本人の問い「位置の蓋然性をどう判定しているか」（2026-11-22）への答えとして書く。

1. seed から決まる9,000個の候補点を地域に散らす。
2. 候補点ごとに、次の規則を上から当てはめ、最初に合った1種類だけを採点する。どれにも合わない点は捨てる。

| 順 | 種類 | 合う条件 | 点が高くなる所 |
|---|---|---|---|
| 1 | 浅瀬に沈んだ遺構 | 水深25〜700mで、近くに陸がある | 水深220mに近い所 |
| 2 | 川辺の段丘 | 川の上 | 上流から集まる水の量が多い所 |
| 3 | 山頂のモノリス | 標高が最高の半分より上で、周りより60m以上高い | 高く、周りから突き出た所 |
| 4 | 雪原のドーム | 雪原・ツンドラ | 周りより高い所 |
| 5 | 海岸のアーチ | 標高60m未満で、すぐそばに海がある | 低い所 |
| 6 | 乾いた平原の環 | 砂漠・サバンナ | 乾いた所 |
| 7 | 丘の塔 | 森・草原で、周りより15m以上高い | 周りから突き出た所 |

3. 種類ごとに点の高い順に並べ、種類を順に回しながら1つずつ選ぶ。既に選んだ地点から距離9未満の候補は飛ばす。18地点になるまで続ける。
4. 点には候補点ごとの小さなゆらぎ（0〜0.2）が足してある。同じ点数の場所が並んだ時に、seed で選び分けるため。

この方式の性質：どの種類も同じ数だけ選ぼうとするので、地域に多い地形（森の丘は候補797）も少ない地形（乾燥地は候補22）も、ほぼ同じ数の地点になる。エリアごとの数は揃えていない（seed 7 で0〜4）。`RegionSite` は、採点（`Score`）・その種類の中の順位と候補数（`Rank` / `Candidates`）・理由の文（`Reason`）・所属エリア（`AreaId`）を持つ。

### 描画（`RegionMapRenderer.Render`）

気温×湿り気の色表の補間、北西315°からの陰影、落ち影、海の水深色、川、雪、雲と雲の影。`RegionMapStyle` は Satellite（写真風）/ Atlas（地図帳風）/ Relief（起伏を強調）。出力は RGBA32（北西の角から行順）。

衛星写真風（本人が選んだ様式）だけが持つ処理:

- 光: 直射光（やや暖色）と空からの光（青み）を分けて足す。日陰は黒く潰れず青黒くなる。
- 陸の色: 植生のむら（広いまとまり・細かなまだら・1セルごとの粒）と谷底の湿りを湿り気へ足してから色表を引く。急斜面は岩肌、森の斜面は岩が出にくい。雪の境目はむらを持つ。
- 川: 流量から幅と濃さを決めた被覆率を作り、軽くぼかす（`BuildRiverCoverage`）。細い川は薄くしか写らない。
- 海: 深い所は暗い紺、明るい青緑は岸のごく近くだけ。細かい模様は向きを回しながら重ねるノイズ（`RegionNoise.FbmTurned`）で作り、升目を出さない。
- 雲: `RegionClouds` が、上下左右のつながる（繰り返せる）雲の層を半分の解像度で作る。大きなまとまり・もこもこした塊・高い所の薄い筋雲を重ね、量は `RegionRenderOptions.CloudCover`（既定 0.58）で決まる。PNG 書き出しでは地図へ描き込み、探索画面では地図へ描き込まずに上へ重ねて流す。
- 探索画面の雲の動き（`RegionCloudFlow`、2026-11-22）: 低い塊の雲と高い筋雲を別の層にし、向きと速さの違う風で流す（高い雲は1.7倍速く、向きも違う）。各層は、場所ごとに渦でずらす（最大で地図の幅の約2.5%）。渦の模様そのものもゆっくり移り変わる。場所ごとに濃さも揺らぐ。影は低い雲だけが落とす。層は升目のメッシュ（`RegionCloudLayer`、32×32）で描き、升目の角ごとに絵を読む位置をずらす。専用のシェーダーは使わない。

## 6. 探索のルールと、ゲームを載せる入口

- 地図座標は X・Y とも 0〜100。X は東へ、Y は南へ増える。高さ（m）は `RegionData.HeightAtMap`。
- `ExplorationSession.Search(x, y)`: いちばん近い未発見の地点との距離で `Found`（2.5以内）/ `Strong`（8以内）/ `Faint`（18以内）/ `None` を返し、`Found` なら発見済みに加える。距離の値は調整用の公開フィールド。
- `ExplorationSession.Sense(x, y)`: 回数を消費せずに反応だけを見る。
- `SaveDiscoveredIds()` / `Restore(ids)`: 発見済みの地点 ID を保存・復元する（保存先は載せるゲームが決める）。
- エリア: `RegionData.Areas`（一覧）、`Area`（セルごとの番号。0は外洋）、`AreaById(id)`、`AreaAtMap(x, y)`、`PlaceNameAtMap(x, y)`（陸は「中央の山地」、岸に近い海は「…の沖」、その外は「北の外洋」）。境界線の絵は `RegionAreas.RenderBoundaries(data)`。
- 地点の根拠: `RegionSite.Score` / `Rank` / `Candidates` / `Reason` / `AreaId` / `Feature`、任意のセルの採点は `RegionSiteGenerator.Rate(data, x, y, out kind, out score)`。
- `RegionExplorer`（MonoBehaviour）: `IsReady`、`Region`、`Session`、`CursorMapPosition`、`MoveCursor(x, y)`、`SearchAtCursor()`、`NextRegion()`、`NextStyle()`、`NextCloudOpacity()`、`NextAreaDisplay()`、`CloudLevel`、`AreaDisplay`、`CloudDrift`。
- 探索画面の操作: 地図を左クリックでカーソル移動、Space / Enter / ボタンでサーチ、矢印キーで微調整、ホイールで拡大、右または中ドラッグで地図を動かす。「雲」ボタンで 濃い → 薄い → なし（衛星写真の時だけ）。「地名」ボタンで 名前 → 名前と境界 → なし。カーソル位置の部品に、その場所のエリア名が出る。低い雲は東南東へ、地図の幅を420秒で横切る速さで流れる（`_cloudCrossSeconds`）。

## 8. 既知の制限

- 湖は生成されない（窪地を毎回埋める）。`RegionBiome.Lake` と `LakeDepth` は場所だけある。
- なだらかな平野に薄い平行な筋が残る（山地の平行な溝と海の升目は2026-11-21に解消）。
- 探索画面の知らせの帯は3〜8秒で消える（生成中・描き直し中・エラーは出したまま）。出ている間は地図の南端に重なる。
- 反応の表示（弱い・強い）は方角を示さない。強い反応の範囲（半径8）は発見の範囲（半径2.5）の約10倍の面積で、その中は総当たりになる。
- 反応の表示は直前のサーチの結果で、カーソルを動かしても次のサーチまで変わらない。
- 生成の下地・気候と描画・雲は行ごとに並列で計算する。侵食は1本のスレッドで、生成時間の大半を占める。探索画面は開始時に生成が終わるまで待つ（Unity Editor で約9〜11秒。ビルドした Player では未確認）。
- 地点の中身、発見後の遷移、音、演出、保存の画面は無い。
- エリアと地点の呼び名は機械的な仮の呼び名で、種類が同じ地点は同じ呼び名になる（例「北東の丘陵・雪原のドーム」が2つ）。エリアの種類は平均の地形で決めるので、雪の峰を含む「丘陵」のように、一部の見た目と合わない所がある。
- 陸に囲まれた海面より低い所は海として扱い、最寄りのエリアに入る（湖として分けない）。
- 地図上のエリア名は、雲・発見カード・下端の案内と重なることがある。重なりを避ける配置はしていない。
- 雲の層は地図より粗い（半分の解像度）。渦のずれを今より大きくすると、雲の絵が筋状に引き伸ばされる。雲が湧く・消える変化は、濃さの揺らぎで見せているだけで、雲の形は作り直していない。
- 探索画面の文字は OS のフォントを使う（Windows で確認）。他の環境の表示は未確認。
- 画面は 1920×1080 を基準に高さへ合わせて縮む。縦長の画面は未対応。
